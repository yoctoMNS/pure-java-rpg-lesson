# pure-java-rpg-lesson

**Javaの経験はあるが、ゲーム制作は初めての人**が受ける入門講座（1本15分 × 全30回）の教材リポジトリです。
Java の**標準クラスライブラリだけ**で、RPGを1本作りきります。

## この講座の2本の柱

| 柱 | 中身 | 扱い方 |
| --- | --- | --- |
| **①ゲームづくりの基礎** | ゲームループ・描画・タイルマップ・当たり判定・シーン・ターン制など | **知らない前提**。用語カードで手厚く（毎回2分30秒） |
| **②オブジェクト指向の使いどころ** | 継承・ポリモーフィズム・抽象クラス・インターフェース・カプセル化 | **知っている前提**。定義ではなく判断基準（毎回1分） |

### この2本は、別々の話ではありません

**ゲームづくりで出てくる問題が、オブジェクト指向の道具をちょうど必要とします。**

| 回 | ①ゲームの側から見ると | ②設計の側から見ると |
| --- | --- | --- |
| 7 | 主人公も町の人も「世界の中にいる物」 | だから共通の親（`Entity`）にまとめられる |
| 8 | 描画順を守って全員を描きたい | だから `List<Entity>` で1つのループにする |
| 17 | 画面ごとにまったく別のゲームになる | だから `Scene` という抽象クラスに分ける |
| 24 | 敵は確率の表から行動を選ぶ | だから行動をインターフェースで差しかえる |

**台本は必ず①から入って②につなげます。**
ゲームの問題を先に見せないと、設計の話がただの理屈になります。

## この講座がやらないこと

| やらないこと | 理由 |
| --- | --- |
| **Javaの文法を教えない** | 受講者は習得済み。継承・インターフェースの「定義」は説明しません |
| **ゲームエンジンを作らない** | 使い回せる汎用の仕組みは作らず、**1本のゲームを作りきる**ことに集中します |
| **本格的な難易度にしない** | 本格版は次シリーズ「2D RPG ゲームエンジン編」で扱います |

```
Java 基礎（他の講座で習得済み）
        ↓
★ この講座：ゲーム制作の基礎を学びながら、オブジェクト指向の使いどころを知る
        ↓
   次シリーズ：2D RPG ゲームエンジン編
```

## 柱① ゲーム制作の用語は、1つ残らず説明します

受講者はゲーム制作が初めてです。**「知っているだろう」で飛ばす言葉は1つもありません。**
説明するゲーム用語は**全55語**（[docs/03_GLOSSARY.md](docs/03_GLOSSARY.md)）。

用語カードは4点セットです。

```
【用語カード】ゲームループ
・ひとことで : ゲームが動き続けるための、ぐるぐる回り続けるしくみ
・中身       : ①入力を見る ②世界を動かす（update） ③画面を描く（draw）
・なぜ必要か : ふつうのプログラムは上から下に処理して終わるが、
               ゲームは「終わらずに回り続ける」必要がある
・たとえ     : パラパラまんが。1枚描く → 少しずらす → また描く
```

**「なぜ必要か」がいちばん大事です。** 仕組みだけ教えても、応用できません。

そして、**見せれば1秒で分かることは実演します**（全30回で義務）。
直接描く版のチラつき／押しっぱなしで会話が飛ぶ／描画順を逆にして主人公が隠れる／
あなあきの紙を大きな紙の上で動かす／MP3を入れて失敗する——など。

## 柱② 先に困らせてから、道具を出す

オブジェクト指向は、**なぜ必要かを体験しないと身につきません。**
**同じコードを2回書いてうんざりしてから**継承を使えば、二度と忘れません。

山場が **5回** あります。

| 回 | 何に困るか | どの道具で解決するか |
| --- | --- | --- |
| **第7回** | `Player` をコピペして `Npc` を作り、30行が重複する | **継承**（`Entity`） |
| **第17回** | `switch` の枝が増え、同じ分岐が2か所にできる | **抽象クラス**（`Scene`） |
| **第24回** | 敵の行動が `if` の連なりになる | **インターフェース**（`MonsterAction`） |
| **第26回** | アイテムの種類ごとに `if` が増える | **抽象クラス**（`Item`）※24回との違いを自分で判断させる |
| **第28回** | セーブしたい状態がどこにあるか探す | **カプセル化の効き目**（もう集まっている） |

そして、**効き目は感想ではなく事実で見せます。**

- 第7回：`Entity` を1行直すと、`Player` と `Npc` が同時に直る
- 第14回：描いたマス数が 1600 → 240 に減る
- **第19・27・28・30回：`git diff GamePanel.java` が差分ゼロ（4回連続）**
- 第28回：状態が2か所に集まっているので、セーブが55行で書ける

### 持ち帰ってほしい1文

> **状態を配りたいなら抽象クラス。約束だけなら インターフェース。**

## 完成する物

そうげん・まち・どうくつを歩き、NPCと会話し、敵と戦い、レベルを上げ、
道具を買って装備し、セーブして続きから遊べる——**1本のRPG**です。

中身の量（モンスター・アイテム・成長表・会話）は**すべて外部ファイルの行数で決まる**ので、
講座が終わったあと、受講者は**コードを1行も書かずに**増やせます。

## 進めかた（制作側の手順）

1. `docs/02_RULES.md` のルール0（2本の柱）とルール1・2を読み返す
2. **「今日のゲームづくり」と「今日のオブジェクト指向」を先に決めてから**、コードを決める
3. 台本を書き、ルール7のチェックリスト20項目で確認する
4. その回の終わりに `git tag ep01` のようにタグを付ける
   （書き直しの回は `ep17-before` と `ep17` の2つ）

### 実装を進めるとき

台本ができたら、`docs/08_IMPLEMENTATION_WORKFLOW.md` の手順でコードを実装します。
**1話＝1コミット＝1タグ**が基本で、授業中は前後のタグの差分（`git diff ep06 ep07`）を見せながら進められます。
