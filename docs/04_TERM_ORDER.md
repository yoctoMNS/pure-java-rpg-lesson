この講座には**2本の柱**があるので、この表も2つあります。

1. **ゲーム用語の登場順**（柱①）… 説明していない言葉を使っていないか

## 3. 「困る → 直す」の山場（5か所）

**この5回が、柱②の価値のほとんどを担っています。**
仕込みと解決が対応しているか、必ず確認します。

| 回 | ①ゲームづくりの下地 | 仕込み（どう困らせるか） | 解決（道具） | 効き目の見せ方 |
| --- | --- | --- | --- | --- |
| **7** | ゲームオブジェクトという考え方 | `Player.java` をコピペして `Npc.java` を作り、2ファイルを左右に並べ、同じ30行に色をつける | 継承（`Entity`） | `Entity` を1行直すと両方が直る |
| **17** | シーンという考え方 | 第16回の宿題で `switch` に `MENU` を足させておく。`update()` と `draw()` の2か所にあると見せる | 抽象クラス（`Scene`） | `GamePanel` の行数が半分になる |
| **24** | 敵AIと確率テーブル | 敵の行動を `if / else if` で4種類書く。`BattleScene` が30行増える | インターフェース（`MonsterAction`） | その場で `HealAction` を足す。`BattleScene` は触らない |
| **26** | アイテムの種類と効果 | `Item` の `use()` に `if (type == ...)` を書く | 抽象クラス（`Item`） | **「どこかで見ませんでしたか？」と問い、第24回を思い出させる** |
| **28** | セーブデータ設計 | 「セーブしたい物を全部書き出してください」と問う | （道具ではなく）**カプセル化の結果** | `Player` と `Flags` の2つだけで済む。55行で書ける |

### 山場の回で必ずやること

1. **①ゲームづくりの説明を先にやる**（省かない。ここが困りの下地になる）
2. **困りを、コードで実際に見せる**（口で言うだけにしない）
3. **問いかけて、画面に3秒のカウントダウンを出して待つ**
4. **判断基準の表を、画面に出す**
5. **効き目を、行数か `git diff` で見せる**
6. **一時停止チャレンジは「道具を使う側」の課題にする**

## 7. チェックのやり方（台本ができたら）

1. **「1. ゲーム用語の登場順」の表**を見て、その回で初出の用語をすべて洗い出す
   - **用語カードが4点セット（ひとことで／中身／なぜ必要か／たとえ）になっているか**
   - **実演が1回以上あるか**
2. **その回より前に出ていない用語を、だまって使っていないか**確認する
3. **「2. オブジェクト指向の登場順」の表**で、道具の順番を確認する
4. 山場の回なら、**「3. 山場」の6項目**を全部やっているか確認する
5. **「4. 伏線と回収」の表**を見て、その回で回収すべき物がないか確認する
6. **「5. 同じ形の使い回し」の表**を見て、「同じ形ですね」と言うべき場面がないか確認する
7. Java の基礎文法の説明が混ざっていないか確認する（**混ざっていたら削る**）
