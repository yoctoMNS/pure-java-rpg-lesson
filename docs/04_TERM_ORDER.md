# 04. オブジェクト指向の道具の登場順（矛盾チェック表）

> **第2版まではJava文法の導入順を管理する表でしたが、
> 受講者がJava基礎を終えている前提になったため、文法の順番管理は不要になりました。**
> かわりに、**オブジェクト指向の道具を、どの順で、どう積み上げるか**を管理します。

このファイルの目的は3つです。

1. 道具が**同じ場面でしか出てこない**ことになっていないか確かめる
2. **「困る → 直す」の山場**が、正しく仕込まれているか確かめる
3. **伏線と回収**が、もれなく対応しているか確かめる

### 順番を入れかえてはいけないところ

- **第7回は、第6回のあと**。`Player` が1つある状態で「もう1つ作る」から困りが生まれる
- **第8回は、第7回のあと**。`Entity` がないと `List<Entity>` が作れない
- **第9回は、第7回のあと**。継承を知ってから「継承ではない方」を出すから、判断基準になる
- **第17回は、第16回のあと**。`switch` を1度書かないと、破綻が実感できない
- **第19回は、第17回の直後が望ましい**。効き目は、覚えているうちに見せる
- **第24回は、第17回のあと**。抽象クラスを知らないと、インターフェースとの比較ができない
- **第26回は、第17回と第24回の両方のあと**。2つを知っているから「自分で選ぶ」課題になる
- **第28回は、第6回と第18回のあと**。守ってきたものが、ここで効く

## 2. 「困る → 直す」の山場（5か所）

**この5回が、この講座の価値のほとんどを担っています。** 仕込みと解決が対応しているか、必ず確認します。

| 回 | 仕込み（どう困らせるか） | 解決（どの道具か） | 効き目の見せ方 |
| --- | --- | --- | --- |
| **7** | `Player.java` をコピペして `Npc.java` を作る。2ファイルを左右に並べ、同じ30行に色をつける | 継承（`Entity`） | `Entity` を1行直すと両方が直る |
| **17** | 第16回の宿題で `switch` に `MENU` を足させておく。`update()` と `draw()` の2か所にあることを見せる | 抽象クラス（`Scene`） | `GamePanel` の行数が半分になる |
| **24** | 敵の行動を `if / else if` で4種類書く。`BattleScene` が30行増える | インターフェース（`MonsterAction`） | その場で `HealAction` を足す。`BattleScene` は触らない |
| **26** | `Item` に `type` を持たせ、`use()` の中で `if (type == ...)` を書く | 抽象クラス（`Item`） | **「どこかで見ませんでしたか？」と問い、第24回を思い出させる** |
| **28** | 「セーブしたい物を全部書き出してください」と問う | （道具ではなく）**カプセル化の結果** | `Player` と `Flags` の2つだけで済む。60行で書ける |

### 山場の回で必ずやること

1. **困りを、コードで実際に見せる**（口で言うだけにしない）
2. **問いかけて、画面に3秒のカウントダウンを出して待つ**
3. **判断基準の表を、画面に出す**
4. **効き目を、行数か `git diff` で見せる**
5. **一時停止チャレンジは「道具を使う側」の課題にする**

## 6. チェックのやり方（台本ができたら）

1. **「今日のオブジェクト指向」が1つに決まっているか**確認する
2. 山場の回なら、**「2. 山場」の表の5項目**を全部やっているか確認する
3. **「3. 伏線と回収」の表**を見て、その回で回収すべき物がないか確認する
4. **「4. 同じ形の使い回し」の表**を見て、「同じ形ですね」と言うべき場面がないか確認する
5. Java の基礎文法の説明が混ざっていないか確認する（**混ざっていたら削る**）
6. 用語を出したら、`03_GLOSSARY.md` の言い方と合っているか確認する
