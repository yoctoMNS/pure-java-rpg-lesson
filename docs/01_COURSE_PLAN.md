# 01. 全30回 チュートリアル計画書（第3版）

1本 **15分** × **30本**（合計 450分 ＝ 7時間30分）

> **この講座の位置づけ**
> **Javaの基礎学習を終えた人**が、次の一歩として受ける**入門講座**です。
>
> 本当の主題は「RPGの作り方」ではありません。
> **「基礎で習ったオブジェクト指向が、実際の場面でどう効いてくるのか」を体で分かること**です。
> RPGは、そのいちばん分かりやすい題材として使っています。
>
> ゲームエンジンのような大がかりな物は作りません。
> 本格的な内容は、この後の別シリーズ「2D RPG ゲームエンジン編」で扱います。

## 受講者について

### 前提としていること（習得済みとみなす）

変数・型・演算子／`if`・`switch`／`for`・`while`／配列／メソッド（引数・戻り値）／
クラスとインスタンス／フィールド・コンストラクタ／`public`・`private`・`static`／
継承・`extends`・`@Override`／インターフェース・`implements`／`abstract`／
`enum`／`ArrayList`・`HashMap`／`try-catch`

**つまり、Javaの入門書を1冊終えた状態**です。これらの文法は説明しません。

### 受講者がかかえている悩み（この講座が答えるもの）

| 悩み | この講座での答え |
| --- | --- |
| 文法は分かるが、**何を作ればいいか分からない** | 作る物を1つ最後まで見せる |
| クラスは書けるが、**どう分ければいいか分からない** | 分け方の判断基準を、実例で毎回示す |
| **継承をいつ使うのか実感がない** | 継承を使わないと困る場面を先に作り、そこで使う（第7回） |
| **インターフェースをいつ使うのか実感がない** | 同じく、困ってから使う（第24回）。全部で4回登場させる |
| **抽象クラスとインターフェースの違いが曖昧** | 両方を実際に使い、使い分けの理由を言葉にする（第17・24・26回） |
| **`private` にする意味が分からない** | `public` にして壊れる例を見せる（第6回） |

### この講座がとる、いちばん大事なやり方

> **先に「困る書き方」で書いてもらい、困ってから、道具で解決します。**

オブジェクト指向は、**なぜ必要かを体験しないと身につきません。**
「継承とは〜です」と説明しても、「へえ」で終わります。
**同じコードを2回書いてうんざりしてから**継承を使うと、二度と忘れません。

この講座には、その「困る→直す」の山場が **5回** あります（第7・17・24・26・28回）。

## 第2回 ウィンドウを出して絵を描く

- **ゴール**: 黒い画面に白い四角が描かれ、ドットが大きく見える
- **今日のオブジェクト指向**: **継承（借りる側）**
  - `JPanel` を継承するのは、**「絵を描く場所」という仕組みをまるごともらうため**
  - `paintComponent` を `@Override` するのは、**「描く中身だけを自分のものに差しかえる」**ため
  - 「他人が用意した流れの中に、自分の処理を割りこませる」——これが継承のいちばん多い使われ方
  - **第7回では、逆に『自分で親を作る側』をやります**と予告する
- **前回までにできていること**: プロジェクトの準備
- **きょうの言葉（ゲーム特有）**:
  - `座標`… 画面の中の位置。**左上が (0,0)**、下に行くと y が増える
  - `BufferedImage`… 目に見えない下書き用の紙
- **さわるファイル**: `Main.java`・`GameWindow.java`・`GamePanel.java`（新規） / **行数のめやす**: 45行
- **15分の流れ**:
  - 0:00-0:30 ゴール（白い四角が大きなドットで出る）
  - 0:30-3:00 **今日のオブジェクト指向**（上記）。`JPanel` のソースを実際に開いて、`paintComponent` が呼ばれる流れを見せる
  - 3:00-5:00 **写経①**: `GameWindow`（`JFrame` を**継承せず**、中で作って使う）
    「`JFrame` は継承する必要がありません。**中身を差しかえたいわけではない**からです。
    ここが `JPanel` との違いです」← 継承と利用の使い分け
  - 5:00-9:00 **写経②**: `GamePanel extends JPanel`。256×240 の `BufferedImage` を持ち、
    `paintComponent` で 768×720 に引きのばして貼る
  - 9:00-10:30 **写経③**: 下書きに黒でぬりつぶし → 白い四角を描く
  - 10:30-12:00 **一時停止チャレンジ**

  - 13:30-15:00 まとめ ／ 宿題 ／ 次回予告
- **一時停止チャレンジ**: 「画面の四すみに、色ちがいの四角を4つ描いてください」

- **宿題**: 画面の大きさや倍率の数字を変えて、見え方を比べる

## 第3回 ゲームループ／1秒に60回

- **ゴール**: 四角がひとりでに動き続ける
- **今日のオブジェクト指向**: **インターフェース①**
  - `ActionListener` は「**時間が来たら、あなたのこのメソッドを呼びます**」という約束
  - インターフェースは「**呼ばれる側になるための札**」。実装すると、`Timer` から呼んでもらえる
  - 「自分が呼ぶ」のではなく「**呼んでもらう**」——この向きの逆転が、インターフェースの典型的な使い方
  - **第24回では、自分がインターフェースを『作る側』になります**と予告
- **前回までにできていること**: 画面に絵が描ける
- **きょうの言葉（ゲーム特有）**:
  - `ゲームループ`… 「動かす → 描く」をくり返し続けるしくみ
  - `FPS`… 1秒間に画面を描きかえる回数（この講座は60）
- **さわるファイル**: `GamePanel.java` / **行数のめやす**: 25行
- **15分の流れ**:
  - 0:00-0:30 ゴール（四角がひとりでに動く）
  - 0:30-1:00 前回のふりかえり
  - 1:00-3:30 **今日のオブジェクト指向**（上記）。
    「`Timer` は、あなたのクラスを知りません。知っているのは `ActionListener` という**約束だけ**です。
    だから、どんなクラスでも札を持っていれば渡せます」
  - 3:30-7:00 **写経①**: `GamePanel implements ActionListener` にして `actionPerformed` を書く
  - 7:00-9:30 **写経②**: `Timer timer = new Timer(1000 / 60, this); timer.start();`
    `this` を渡す意味を説明（「約束を守っている自分自身を渡す」）
  - 9:30-11:00 **写経③**: `update()`（動かす）と `repaint()`（描く）に分ける。
    **この2つを分けるのが、ゲームの基本形**
  - 11:00-12:30 **一時停止チャレンジ**
  - 12:30-13:30 **なぜスレッドを使わないか**：`Timer` は Swing の描画と同じ流れで動くので安全。
    スレッドを使うと、描いている最中に位置が変わって表示が乱れることがある
  - 13:30-15:00 まとめ ／ 宿題 ／ 次回予告
- **一時停止チャレンジ**: 「四角が画面の右はしまで行ったら、左はしに戻るようにしてください」
- **動かして確かめること**: 四角が流れる。`1000/60` を `1000/5` にすると遅くなる
- **つまずきポイント**: `repaint()` の呼び忘れ／`actionPerformed` を書かずに赤い線が出る
- **宿題**: `update()` と `draw()` の役わりを、コメントで自分の言葉で書く

## 第4回 キー入力／押されたキーを覚える

- **今日のオブジェクト指向**: **インターフェース②** ＋ **責任の分離**

  - 分ける理由：「`GamePanel` の仕事は『まとめること』。**キーの細かい話まで抱えると、読めなくなる**」
  - **1クラス1つの仕事**という判断基準を、ここで初めて言葉にする
- **前回までにできていること**: ゲームループが回っている
- **さわるファイル**: `KeyHandler.java`（新規）、`GamePanel.java` / **行数のめやす**: 40行
- **15分の流れ**:
  - 0:00-0:30 ゴール（キーで四角が動く）
  - 0:30-1:00 ふりかえり
  - 1:00-3:00 **今日のオブジェクト指向**（上記）。

  - 9:00-10:30 **写経③**: `update()` の中で `if (keyHandler.up) { ... }`

## 第5回 画像を読んで描く

- **きょうの言葉（ゲーム特有）**:
  - `タイル`… マップを作る小さな四角い絵（この講座では 16×16 ピクセル）
  - `リソース`… 絵・音・データなど、プログラム以外の材料
- **さわるファイル**: `ImageLoader.java`（新規）、`res/` に素材、`GamePanel.java` / **行数のめやす**: 30行
- **15分の流れ**:
  - 0:00-0:30 ゴール（絵が出る）

## 第17回 `switch` が破綻する → 抽象クラスで解決 ★

> **この講座2つ目の山場です。**
> **抽象クラスとインターフェースの違いが分からない**、という悩みに、ここで正面から答えます。

    「戦闘・店・タイトルを足すと、`switch` の枝は6本 × 2か所 ＝ 12か所になります」
  - → `abstract class Scene { abstract void update(); abstract void draw(Graphics g); }`
  - `FieldScene` / `MessageScene` が `Scene` を継承。`GamePanel` は `currentScene` を1つ持つだけ
  - **`GamePanel` の `update()` は `currentScene.update();` の1行になる**
  - **効き目**: 「**新しい画面を足しても、`GamePanel` は1行も変わりません**」
  - **なぜインターフェースではなく抽象クラスか**（ここが本題）
    | | 使うのはこちら |
    | --- | --- |
    | 共通の**状態**（フィールド）がある | **抽象クラス** |
    | 共通の**処理**を親に書きたい | **抽象クラス** |
    | 振る舞いの**約束だけ**したい | インターフェース |
    | 別の親をすでに継承している | インターフェース（Javaは親を1つしか持てない） |
    - `Scene` は `game` への参照と、`enter()` の共通処理を持たせたい → **抽象クラス**
    - **第24回では、逆にインターフェースが正解の場面を出します**と予告
- **前回までにできていること**: `enum` と `switch` で画面を分けている
