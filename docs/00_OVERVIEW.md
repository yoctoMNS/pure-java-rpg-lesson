# 00. 講座の全体像

## 1. 受講者

> **Javaの経験はあるが、ゲーム制作は初めての人**

この一文が、この講座の設計をすべて決めています。

| | 受講者の状態 | だから、こう教える |
| --- | --- | --- |
| **Java** | 知っている | 文法は説明しない。「いつ使うか」だけを扱う |
| **ゲーム制作** | **初めて** | **考え方と用語を、1つ残らず手厚く説明する** |

## 2. この講座の2本の柱

### この2本は、別々の話ではありません

**ゲームづくりで出てくる問題が、オブジェクト指向の道具をちょうど必要とします。**

| 回 | ①ゲームの側から見ると | ②設計の側から見ると |

## 4. 教え方の4つの柱

### 柱1. ゲームの用語は、1つ残らず用語カードで説明する

受講者はゲーム制作が初めてです。**「知っているだろう」で飛ばす言葉は1つもありません。**

用語カードは4点セットです。

```
【用語カード】ゲームループ
・ひとことで : ゲームが動き続けるための、ぐるぐる回り続けるしくみ
・中身       : ①入力を見る ②世界を動かす（update） ③画面を描く（draw）
・なぜ必要か : ふつうのプログラムは上から下に処理して終わるが、
               ゲームは「終わらずに回り続ける」必要がある
・たとえ     : パラパラまんが。1枚描く → 少しずらす → また描く
```

**「なぜ必要か」がいちばん大事です。** 仕組みだけ教えても、応用できません。

説明するゲーム用語は**全55語**。すべて `03_GLOSSARY.md` に載っています。

### 柱2. 見せれば1秒で分かることは、実演する

ゲームの話は、言葉より実演のほうが速いことがほとんどです。**毎回1回以上、必ず入れます。**

| 回 | 実演すること |
| --- | --- |
| 2 | 直接描く版を見せて、チラチラするのを体験してもらう |
| 4 | 会話送りを「押しっぱなし」で作り、1回押しただけで飛ぶのを見せる |
| 8 | 描画順を逆にして、主人公が地面の下に隠れるのを見せる |
| 13 | 通れないマスに赤い枠を描く（見えない物を見えるようにする） |
| 14 | あなあきの紙を、大きな紙の上で実際に動かす |
| 19 | 遭遇率を「3歩に1回」にして、うんざりするのを体験してもらう |
| 20 | コピーを作らないと、2回目に瀕死の敵が出るのを見せる |
| 23 | `DamageCalc` を1000回呼んで、ダメージの分布を数字で出す |
| 29 | MP3を入れて失敗するところを実演する |

### 柱3. 先に困らせてから、オブジェクト指向の道具を出す

> オブジェクト指向は、**なぜ必要かを体験しないと身につきません。**

「継承とは〜です」と説明しても「へえ」で終わります。
**同じコードを2回書いてうんざりしてから**継承を使えば、二度と忘れません。

山場が **5回** あります。

| 回 | 何に困るか | どの道具で解決するか |
| --- | --- | --- |
| **第7回** | `Player` をコピペして `Npc` を作り、30行が重複する | **継承**（`Entity`） |
| **第17回** | `switch` の枝が増え、同じ分岐が2か所にできる | **抽象クラス**（`Scene`） |
| **第24回** | 敵の行動が `if` の連なりになる | **インターフェース**（`MonsterAction`） |
| **第26回** | アイテムの種類ごとに `if` が増える | **抽象クラス**（`Item`）※24回との違いを自分で判断させる |
| **第28回** | セーブしたい状態がどこにあるか探す | **カプセル化の効き目**（もう集まっている） |

### 柱4. 「効き目」は、感想ではなく事実で見せる

「きれいになりました」「保守性が上がります」は**禁止**です。

- 第7回：`Entity` を1行直すと、`Player` と `Npc` が同時に直る
- 第8回：その場でNPCを5人に増やす。`add` を2行足すだけで動く
- 第14回：描いたマス数が 1600 → 240 に減る
- **第19・27・28・30回：`git diff GamePanel.java` が差分ゼロ（4回連続）**
- 第23回：`DamageCalc` を1000回呼んで、分布を数字で出す
- 第28回：状態が2か所に集まっているので、セーブが55行で書ける

## 5. 使う道具

| 道具 | 何を使うか |
| --- | --- |
| Java の本体 | **JDK 25** |
| 開発ソフト | **Eclipse** |
| 追加の部品 | **なし**（標準クラスライブラリのみ） |

### 標準クラスライブラリだけで、どこまでできるか

| やりたいこと | 使うもの |
| --- | --- |
| ウィンドウを出す | `javax.swing`（JFrame, JPanel） |
| ゲームループ | `javax.swing.Timer`（**スレッドは使いません**） |
| 絵を描く | `java.awt`（Graphics, BufferedImage） |
| 画像ファイルを読む | `javax.imageio`（ImageIO） |
| キーボード入力 | `java.awt.event`（KeyListener） |
| 文字（フォント） | `java.awt.Font` |
| ファイルの読み書き | `java.nio.file`（Files） |
| セーブデータ | `java.util.Properties` |
| 音 | `javax.sound.sampled`（Clip） |

> **なぜスレッドを使わないか**
> `javax.swing.Timer` は画面を描く流れと同じ場所で動くので安全です。
> スレッドを使うと、描いている最中に位置が変わって表示が乱れることがあります。
> **並行処理はこの講座の主題ではありません。**

> **音についての注意**
> Javaの標準機能で鳴らせるのは **WAV / AIFF / AU** です。**MP3 は鳴りません。**
> これは第29回で受講者がいちばんつまずく所なので、実演で見せます。

## 6. 作る物の仕様

### 画面

| 項目 | 決めた値 |
| --- | --- |
| 論理解像度（ゲームの中の画面） | **256 × 240** ピクセル |
| ウィンドウ | **768 × 720** ピクセル（3倍） |
| 1マス | **16 × 16** ピクセル |
| FPS | **60** |

### 戦闘

| 項目 | 決めた値 |
| --- | --- |
| 見え方 | フロントビュー（敵だけが正面に見える） |
| 人数 | 味方 **1人** ／ 敵 **1体** |
| コマンド | たたかう／じゅもん／ぼうぎょ／どうぐ／にげる／さくせん |
| 行動順 | すばやさ ＋ 乱数 |
| ダメージ | `(こうげき力 − しゅび力 ÷ 2)` × **±25%**。最低 1 |
| 会心の一撃 | 32回に1回くらい。しゅび力を無視 |
| 敵の行動 | 確率テーブルから選ぶ（**実装はインターフェースで差しかえ**／第24回） |

### 中身の規模（入門講座として、あえて小さく）

| 項目 | 決めた値 |
| --- | --- |
| レベル | **1 〜 10** |
| モンスター | **5種類 ＋ ボス1体** |
| じゅもん | **2つ** |
| アイテム | **6個** |
| マップ | **3枚**（そうげん・まち・どうくつ） |
| NPC | **4人** |
| セーブ | **1か所** |

**規模はすべて外部ファイルの行数で決まるように作ります。**
講座が終わったあと、受講者は**コードを1行も書かずに**中身を増やせます。

## 9. 制作の前提

- **1回で新しく書くコードの上限**
  - 第1〜10回: **40行** ／ 第11〜20回: **50行** ／ 第21〜30回: **55行**
  - 上限の合計は1,450行。**実際の見積もりは約1,230行**
  - **第3版より5行ずつ下げました。**「今日のゲームづくり」に2分30秒を使うためです
- **書き直しは意図的に入れます**（第7・17・24・26回）。書き直しの体験そのものが教材です
- 各回の完成コードは **git のタグ**（`ep01` 〜 `ep30`）で残します
  （書き直しの回は `ep17-before` と `ep17` の2つ）

## 10. 気をつけているリスクと、その対策

| リスク | 対策 |
