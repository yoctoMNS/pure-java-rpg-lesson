# 00. 講座の全体像

## 1. この講座の位置づけ

> **Javaの基礎学習を終えた人が、次の一歩として受ける入門講座です。**
>
> 本当の主題は「RPGの作り方」ではありません。
> **基礎で習ったオブジェクト指向が、実際の場面でどう効いてくるのかを体で分かること**です。

### 3つの「やらないこと」

| やらないこと | 理由 |
| --- | --- |
| **Javaの文法を教えない** | 受講者は習得済み。変数・if・ループ・クラス・継承・インターフェースの説明はしません |
| **ゲームエンジンを作らない** | 使い回せる汎用の仕組みは作りません。**1本のゲームを作りきる**ことに集中します |
| **本格的な難易度にしない** | 本格版は別シリーズ「2D RPG ゲームエンジン編」で扱います |

### この講座のシリーズ内での位置

```
Java 基礎（他の講座で習得済み）
        ↓
★ この講座：RPGを1本作りながら、オブジェクト指向の使いどころを知る
        ↓
   次シリーズ：2D RPG ゲームエンジン編（使い回せる形にしていく）
```

## 2. 受講者について

### 前提としていること（説明しません）

変数・型・演算子／`if`・`switch`／`for`・`while`／配列／メソッド／
クラスとインスタンス／フィールド・コンストラクタ／`public`・`private`・`static`／
継承・`extends`・`@Override`／インターフェース・`implements`／`abstract`／
`enum`／`ArrayList`・`HashMap`／`try-catch`

**Javaの入門書を1冊終えた状態**を想定しています。

### 受講者がかかえている悩みと、この講座の答え

| 悩み | 答え方 |
| --- | --- |
| 文法は分かるが、何を作ればいいか分からない | 作る物を1つ、最後まで見せる |
| クラスは書けるが、どう分ければいいか分からない | 分け方の**判断基準**を、実例で毎回示す |
| 継承をいつ使うのか実感がない | **継承がないと困る状況を作ってから**使う（第7回） |
| インターフェースをいつ使うのか実感がない | 同じく、困ってから使う（第24回） |
| 抽象クラスとインターフェースの違いが曖昧 | **両方を実際に使い**、選んだ理由を毎回言葉にする（第17・24・26回） |
| `private` にする意味が分からない | `public` にして壊れる例を見せる（第6回） |

## 3. 教え方の3つの柱

### 柱1. 先に困らせてから、道具を出す

> オブジェクト指向は、**なぜ必要かを体験しないと身につきません。**

「継承とは〜です」と説明しても「へえ」で終わります。
**同じコードを2回書いてうんざりしてから**継承を使えば、二度と忘れません。

この講座には、その山場が **5回** あります。

| 回 | 何に困るか | どの道具で解決するか |
| --- | --- | --- |
| **第7回** | `Player` をコピペして `Npc` を作り、30行が重複する | **継承**（`Entity`） |
| **第17回** | `switch` の枝が増え、同じ分岐が2か所にできる | **抽象クラス**（`Scene`） |
| **第24回** | 敵の行動が `if` の連なりになる | **インターフェース**（`MonsterAction`） |
| **第26回** | アイテムの種類ごとに `if` が増える | **抽象クラス**（`Item`）— 24回との違いを自分で判断させる |
| **第28回** | セーブしたい状態がどこにあるか探す | **カプセル化の効き目**（もう集まっている） |

### 柱2. 同じ道具を、違う場面で何度も出す

**1回きりの説明で終わる道具は1つもありません。**

| 道具 | 出てくる回 | 回数 |
| --- | --- | --- |
| ポリモーフィズム | 8, 17, 19, 24, 26, 27 | **6回** |
| 継承 | 2, 7, 17, 19, 26 | **5回** |
| インターフェース | 3, 4, 24, 29 | **4回** |
| カプセル化 | 6, 13, 18, 28 | **4回** |
| 単一責任（分ける） | 4, 5, 23, 29 | **4回** |
| コンポジション | 9, 20, 27 | **3回** |
| 抽象クラス | 17, 26 | **2回** |

### 柱3. 「効き目」を、その場で必ず見せる

道具を使ったら、**必ずその効果を目の前で見せます。**

- 第7回：`Entity` を1行直すと、`Player` と `Npc` が同時に直る
- 第8回：NPCを5人に増やしても、ループは1行も変わらない
- 第19回：戦闘画面を足しても、`GamePanel` の `git diff` がゼロ
- 第24回：新しい敵の行動を足しても、`BattleScene` は触らない
- 第28回：状態が集まっていたから、セーブが60行で書ける

**「便利になった気がする」ではなく、「差分がゼロだった」という事実で見せます。**

## 4. 使う道具

| 道具 | 何を使うか |
| --- | --- |
| Java の本体 | **JDK 25** |
| 開発ソフト | **Eclipse** |
| 追加の部品 | **なし**（標準クラスライブラリのみ） |

### 標準クラスライブラリだけで、どこまでできるか

| やりたいこと | 使うもの |
| --- | --- |
| ウィンドウを出す | `javax.swing`（JFrame, JPanel） |
| ゲームループ | `javax.swing.Timer`（**スレッドは使いません**） |
| 絵を描く | `java.awt`（Graphics, BufferedImage） |
| 画像ファイルを読む | `javax.imageio`（ImageIO） |
| キーボード入力 | `java.awt.event`（KeyListener） |
| 文字（フォント） | `java.awt.Font` |
| ファイルの読み書き | `java.nio.file`（Files） |
| セーブデータ | `java.util.Properties` |
| 音 | `javax.sound.sampled`（Clip） |

> **なぜスレッドを使わないか**
> `javax.swing.Timer` は Swing の描画と同じ流れで動くので安全です。
> スレッドを使うと、描いている最中に位置が変わって表示が乱れることがあります。
> **この講座の主題はオブジェクト指向なので、並行処理の話に時間を使いません。**

> **音についての注意**
> Javaの標準機能で鳴らせるのは **WAV / AIFF / AU** です。**MP3 は鳴りません。**

## 5. 作る物の仕様

### 画面

| 項目 | 決めた値 |
| --- | --- |
| ゲームの中の画面 | **256 × 240** ピクセル |
| ウィンドウ | **768 × 720** ピクセル（3倍） |
| 1マス | **16 × 16** ピクセル |
| 1秒間に描く回数 | **60回** |

### 戦闘

| 項目 | 決めた値 |
| --- | --- |
| 見え方 | フロントビュー（敵だけが正面に見える） |
| 人数 | 味方 **1人** ／ 敵 **1体** |
| コマンド | たたかう／じゅもん／ぼうぎょ／どうぐ／にげる／さくせん |
| 行動順 | すばやさ ＋ 乱数 |
| ダメージ | `(こうげき力 − しゅび力 ÷ 2)` × **±25%**。最低 1 |
| 会心の一撃 | 32回に1回くらい。しゅび力を無視 |
| 敵の行動 | 確率の表から選ぶ（**実装はインターフェースで差しかえ**／第24回） |

### 中身の規模（入門講座として、あえて小さく）

| 項目 | 決めた値 |
| --- | --- |
| レベル | **1 〜 10** |
| モンスター | **5種類 ＋ ボス1体** |
| じゅもん | **2つ** |
| アイテム | **6個** |
| マップ | **3枚**（そうげん・まち・どうくつ） |
| NPC | **4人** |
| セーブ | **1か所** |

**規模はすべて外部ファイルの行数で決まるように作ります。**
講座が終わったあと、受講者は**コードを1行も書かずに**中身を増やせます。

## 8. 制作の前提

- **1回で新しく書くコードの上限**
  - 第1〜10回: **45行** ／ 第11〜20回: **55行** ／ 第21〜30回: **60行**
  - 上限の合計は1,600行。**実際の見積もりは約1,380行**
- **書き直しは「教材として」意図的に入れます**（第7・17・24・26回）。
  未経験者向けなら避けるべきですが、**この講座では書き直しの体験そのものが教材**です
- 各回の完成コードは **git のタグ**（`ep01` 〜 `ep30`）で残します

## 9. 気をつけているリスクと、その対策

| リスク | 対策 |
| --- | --- |
| 「オブジェクト指向の話」が抽象的になって退屈する | **必ず先に困らせる**。困っていない状態で道具の説明をしない |
| 「効き目」が伝わらない | `git diff` や行数の前後比較で、**事実として見せる** |
| 書き直しの回で受講者が迷子になる | 1つずつ移して、そのつど動かす。前のコードはタグで残す |
| ゲームの作りこみに気を取られて主題がぼやける | 尺があふれたら**ゲームの機能から削る**。「今日のオブジェクト指向」は絶対に削らない |
| Eclipse が JDK 25 に未対応 | 第1回で確認手順を入れる |
| 素材のライセンス違反 | CC0 と OFL だけ（`05_ASSETS.md`）。`assets/CREDITS.md` に記録 |
