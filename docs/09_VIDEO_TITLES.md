### 一致していた原則

| 原則 | 内容 | 出典の一致度 |
| --- | --- | --- |
| **文字数上限** | システム上限は100文字だが、それを使い切ってはいけない | 全出典が一致 |
| **表示は途中で切れる** | デスクトップ検索で約60〜70文字、モバイルは45〜60文字で「…」表示になる | 英語圏の出典が一致 |
| **日本語は全角28〜30文字が目安** | 全角換算で28〜30文字を超えるとスマホで見切れる | 日本語の出典が一致 |
| **キーワードは冒頭に置く** | 最初の3〜5語、または冒頭30〜40文字にいちばん重要な語を置く（英語圏）／冒頭15文字以内（日本語圏） | 双方の出典が一致 |
| **検索意図に合う自然な言葉を使う** | 実際に人が検索窓に打つ言葉に寄せる。SEO記事っぽい機械的な羅列は避ける（vidIQ） | 複数出典が一致 |
| **タイトルは唯一の要素ではない** | サムネイルとタイトルの合計でクリック率の9割以上を決める（YouTube公式）。両者は「繰り返す」のではなく「補い合う」 | YouTube公式が明言 |
| **具体的な数字は信頼感につながる** | 抽象的な言葉より、具体的な数字のほうが内容を把握しやすい | 日本語の出典が一致 |

### この講座への適用方針

1. **全角28〜30文字を目安に、上限は絶対に40字（生の文字数）を超えない**
   （英語やアルファベット・数字は半角として視認幅では0.5文字ぶんに軽く見積もれるため、
   "Java" のようなアルファベットを含む分は多少余裕がある）
2. **冒頭に、その回でいちばん検索されそうな言葉を置く**
   - 継承・カプセル化・抽象クラス・インターフェースなど、**Java学習者が実際にGoogle/YouTubeで
     検索する定番の疑問**（例:「継承 いつ使う」「抽象クラス インターフェース 違い」）は、
     検索ボリュームが大きく見込めるため、該当回はこれを主役キーワードにする
   - ゲーム制作の用語（ゲームループ・タイルマップ・当たり判定・セーブ機能など）は、
     「Java ゲーム制作」という掛け合わせ自体がニッチで需要のある検索語のため、これも積極的に使う
3. **シリーズ全体で統一フォーマットを使う**：`【JavaでRPG制作#◯】<キーワードを含む本文>`
   - 冒頭の【】に "Java" というビッグキーワードと "RPG制作" という具体語を両方含める
   - 回数を入れることで、シリーズ物として視聴者にもアルゴリズムにも認識されやすくする
   - **タイトルをSEO文っぽくしすぎない**：本文側は「〜の作り方」「〜とは？」など、
     実際に人が話す自然な言葉にする（vidIQの助言）
4. **誇張やクリックベイトは使わない**：この講座は学習者向けの信頼性が重要なので、
   「衝撃の」「誰でも簡単に」のような煽り文句は使わない（Re-HERO・keywordmap 双方が、
   教育・ビジネス系コンテンツでは誠実さが再生維持率に直結すると指摘）
5. **サムネイルとの役割分担**：タイトルには結論・キーワードを書き、
   サムネイルには「Before/After」や「困っている顔」など感情面を持たせる
   （動画制作時にサムネイル担当へ申し送りする前提。本ドキュメントはタイトルのみ扱う）

## 4. 運用メモ

- **サムネイルとタイトルの文言を完全一致させない**（YouTube公式ガイドの明言）。
  タイトルに書いた結論やキーワードを、サムネイルでは表情・Before/Afterなど別の角度で見せる
- **概要欄の1行目にもタイトルと同じ主要キーワードを入れる**と、検索でのヒット率がさらに上がります
  （本ドキュメントはタイトルのみを扱うため、概要欄のテンプレートは別途必要になれば追加します）
- タイトルの「#◯」表記は、シリーズ再生リスト名にも同じ命名規則（例:「JavaでRPG制作」）を使うと、
  検索結果・関連動画の両方で一貫性が出ます
- 収録内容が変更になった場合（`01_COURSE_PLAN.md` の該当回が変わった場合）は、
  このファイルのタイトルも合わせて見直してください
