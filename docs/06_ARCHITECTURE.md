このファイルは**制作側だけが見る設計図**です。動画では、ここまで先の話はしません。
ただし、**このとおりに作れば、30回の途中で書き直しが起きない**ことを保証するために、先に決めておきます。

## 1. パッケージは作りません

初心者に `package` の説明をすると、フォルダとファイルの関係でつまずきます。
そこで、**すべてのクラスを `src` の直下に置きます。**

- クラスは全部で **34個**（enum を含む）。1つのフォルダに並びますが、`package` の説明をするより安全です
- Eclipse の左側のツリーは名前順に並ぶので、探すのに困りません
- 第30回の「これからの一歩」で、「`package` で分けると整理できます」と名前だけ紹介します

## 3. 「まとめ役」の構造

初心者にとって、**どこから読めばよいか分かること**が何より大切です。
そこで、次の2つだけを「まとめ役」とし、それ以外は道具に徹します。

```
Main
 └ GameWindow        … ウィンドウを開くだけ
     └ GamePanel     ★まとめ役1: ゲームループと、画面の切りかえ
         ├ FIELD    のとき → TileMap / Camera / Player / Npc / MessageWindow
         ├ BATTLE   のとき → BattleScene   ★まとめ役2: 戦闘のすべて
         ├ MENU     のとき → CommandMenu / Inventory
         └ TITLE / GAMEOVER のとき → GamePanel 内のメソッド
```

**決まりごと**
- `GamePanel` の `update()` と `draw()` は、`switch (sceneType)` で分ける。それ以上のことはしない
- 計算は必ず、それ専用のクラス（`DamageCalc` など）に置く。`BattleScene` の中に計算式を書かない
- データを読む処理は必ず `〜Table` という名前のクラスに置く

## 5. 決めておいた数字（コードの定数）

`GamePanel` の上のほうに、**まとめて**書きます。

```java
// ---- 画面の決まり ----
public static final int TILE_SIZE   = 16;   // 1マスの大きさ（ピクセル）
public static final int SCREEN_COL  = 16;   // 画面によこに入るマス数
public static final int SCREEN_ROW  = 15;   // 画面にたてに入るマス数
public static final int GAME_WIDTH  = 256;  // 16 × 16
public static final int GAME_HEIGHT = 240;  // 16 × 15
public static final int SCALE       = 3;    // 何倍に引きのばすか
public static final int FPS         = 60;   // 1秒間に描く回数
```

**この形にした理由**: 数字が1か所にまとまっていると、「画面を大きくしたい」というときに
1行直せば済みます。第9回で、この考え方を教えます。

## 6. 作らないと決めたもの（大事な線引き）

**これは入門講座です。**「あったほうが良いけれど、教えることが増えすぎる」物は作りません。
第30回の「これからの一歩」で、名前だけ紹介します。

| 作らないもの | 理由 |
| --- | --- |
| 仲間（パーティ複数人） | 戦闘の作りが一気に難しくなる。ターゲット選択も必要になる |
| 敵が複数体 | 同じ理由 |
| スレッドを使ったゲームループ | `Timer` で足りる。目に見えない物の説明が増えるだけ |
| デルタタイム（動きの時間補正） | 60FPS固定で十分。中学までの算数を超える |
| セーブデータの暗号化 | 説明に時間がかかる。第29回の宿題で「書きかえられること」を体験してもらう |
| アイテムを売る機能 | 買うだけで、ゴールドの使いみちは足りる |
| マップエディタ | 表計算ソフトでCSVを書けば十分（第15回の宿題で紹介） |
| セリフの自動改行（漢字まじり） | ひらがな・カタカナだけなら、文字数で数えれば足りる |
| `package` によるフォルダ分け | ファイルとフォルダの関係でつまずく |
| `record`・ラムダ式・ストリーム | 説明を増やさない。第30回で名前だけ紹介 |

## 7. コードの量の見積もり

| 部 | 回 | 新しく書く行数（合計） |
| --- | --- | --- |
| 第0部 はじめる | 1〜2 | 約 10行 |
| 第1部 絵のないRPG | 3〜7 | 約 120行 |
| 第2部 画面に出す | 8〜12 | 約 100行 |
| 第3部 マップ | 13〜17 | 約 145行 |
| 第4部 キャラクター | 18〜19 | 約 80行 |
| 第5部 文字と会話 | 20〜22 | 約 115行 |
| 第6部 たたかい | 23〜27 | 約 210行 |
| 第7部 しあげ | 28〜30 | 約 135行 |
| **合計** | | **約 915行** |

- 1回あたり平均 **約31行**。各回の上限（第1〜7回:25／第8〜17回:40／第18〜30回:45）に収まっています
- 上限をすべて使い切ると 1,160行になりますが、**見積もりは約915行**です。
  この差（約245行）が、説明・失敗例・一時停止チャレンジに使える余裕です
- 第1版の見積もり（約1,690行）から**半分近くまで減りました**。減らせたのは、
  「本格的な物を作らなくてよい」と決まり、規模を外部ファイルで調整する作りにしたからです
- **上限に余裕があるのは意図的です。** 説明・失敗例・一時停止チャレンジに時間を使うためです
