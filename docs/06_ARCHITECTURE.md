# 06. 完成形の設計図（どの回で、何が生まれるか）

制作側だけが見る設計図です。動画では、ここまで先の話はしません。

> **設計方針**
> 受講者は **Javaは知っているが、ゲーム制作は初めて**です。だから設計は次の2つを満たします。
>
> 1. **ゲーム制作の定番の形をそのまま見せる**（ゲームループ・シーン・エンティティ・タイルマップ）。
>    どのゲームエンジンにも出てくる形なので、この講座のあとにも役立ちます
> 2. **オブジェクト指向の道具が効く場面を作る**（第7・17・24・26・28回）
>
> **使い回せる汎用の仕組み（ゲームエンジン）は作りません。**
> 1本のゲームを作りきることに集中します。汎用化は次シリーズの仕事です。

---

## 1. パッケージは作りません

すべてのクラスを `src` の直下に置きます。クラスは **46個**（interface と enum を含む）。

- `package` の説明に時間を使わないため（主題はオブジェクト指向の**使いどころ**）
- Eclipse のツリーは名前順に並ぶので、探すのに困りません
- 第30回で「次シリーズでは `package` で整理します」と触れます

### この設計のいちばん大事な点

**第17回で `Scene` を作ったあと、`GamePanel` は一度も変わりません。**

- 第19回 `BattleScene` → `GamePanel` 無変更
- 第27回 `ShopScene` → `GamePanel` 無変更
- 第28回 `TitleScene` → `GamePanel` 無変更
- 第30回 `GameOverScene` / `EndingScene` → `GamePanel` 無変更

**この「4回連続で無変更」が、抽象クラスの効き目の証拠**です。
毎回 `git diff GamePanel.java` を見せてください。

同じことが第24回以降の `BattleScene` にも起きます
（`MonsterAction` を実装したクラスを足しても、`BattleScene` は無変更）。

## 3. 構造の全体像

```
Main
 └ GameWindow                 … JFrame を「使う」だけ（継承しない）
     └ GamePanel              … ゲームループ（Timer）と、currentScene を1つ持つ
         └ Scene（abstract）  ★第17回。update() / draw() を子に書かせる
             ├ FieldScene     … TileMap / Camera / List<Entity>
             ├ MessageScene   … MessageWindow
             ├ BattleScene    … Monster / CommandMenu / DamageCalc
             │                     └ Monster が List<MonsterAction> を持つ ★第24回
             ├ ShopScene      … CommandMenu / Inventory
             ├ TitleScene     … CommandMenu / SaveManager
             ├ GameOverScene
             └ EndingScene

Entity（abstract ではない。普通のクラス）★第7回
 ├ Player   … HP・レベル・持ち物（すべて private）
 └ Npc      … セリフID
     └ どちらも Sprite を「持つ」 ★第9回
```

**決まりごと**
- `GamePanel.update()` は `currentScene.update();` の1行だけ。それ以上のことはしない
- 計算は専用クラスに置く（`DamageCalc`）。`BattleScene` に計算式を書かない
- 読みこみは `〜Loader` / `〜Table` に置く
- 状態を変える処理は、その状態を持つクラスに置く（`Player.damage()`、`Player.addExp()`）

### `Entity` を `abstract` にしない理由

`Entity` は「マップの上を動くもの」として、そのまま使える形にしておきます。
`abstract` にすると、第7回で説明することが1つ増えます。
**抽象クラスは第17回で、必要になった場面で出します。**

## 6. 作らないと決めたもの

**この講座は入門講座で、ゲームエンジンを作る講座ではありません。**
次の物は、第30回で「次シリーズで扱います」と紹介するだけにします。

| 作らないもの | 理由 |
| --- | --- |
| `SceneManager`（画面の管理クラス） | `GamePanel` が `currentScene` を1つ持てば足りる |
| リソース管理のしくみ（キャッシュ・解放） | `ImageLoader` で足りる |
| イベントの仕組み（リスナーの自作） | 説明が増え、主題から外れる |
| ジェネリクスを使った汎用の入れもの | **次シリーズの主役** |
| 設定ファイル・デバッグ表示 | 主題に関係しない |
| 仲間（パーティ複数人）／敵が複数体 | 戦闘の作りが一気に難しくなる |
| スレッドを使ったゲームループ | `Timer` で足りる。並行処理は主題ではない |
| デルタタイム | 60FPS固定で足りる |
| セーブデータの暗号化 | 主題に関係しない |
| マップエディタ | 表計算ソフトでCSVを書けば足りる |
