# 02. 制作ルール

この講座を作るときに、**必ず守る決まりごと**です。
台本を書く人・コードを書く人・動画を編集する人、全員がこれに従います。

---

## ルール1. 話しことばのルール（いちばん大事）

### 1-1. 使ってよい言葉のレベル

> **中学校を卒業するまでに習う言葉だけで説明します。**
> 高校から先で習う言葉・考え方は、解説の文章に出してはいけません。

理由：この講座は「プログラム未経験の人」だけを相手にしているからです。
むずかしい言葉が1つ出ただけで、その人はそこで止まってしまいます。

### 1-2. 算数・数学のライン

| 使ってよい（中学まで） | 使ってはいけない（高校から） |
| --- | --- |
| 足す・引く・かける・わる／あまり | 三角関数（sin・cos・tan） |
| 小数・分数・割合・百分率（％） | 対数・指数関数 |
| 正の数・負の数 | ベクトル・行列 |
| 座標（たて・よこの位置） | 微分・積分 |
| 比例 | 数列・階乗・組み合わせの式 |
| 確率（「4回に1回くらい」） | 期待値・標準偏差 |
| 平方根（※使わない方針） | 二進数・十六進数・ビット |

**言いかえの例**

| 言いたいこと | ダメな言い方 | 良い言い方 |
| --- | --- | --- |
| 25%の確率で当たる | 「確率25％の事象」 | 「**4回に1回くらい**の割合で当たります」 |
| 音を小さくする | 「音量をデシベルで対数指定」 | 「**-10 と入れると小さくなります**。数字の意味は表にしておきました」 |
| 平均するとこのくらい | 「期待値は12です」 | 「**何回もやってならすと、だいたい12**になります」 |
| ななめに動かす | 「ベクトルを合成して」 | 「**よこに3、たてに2**、同時にずらします」 |

> **音量の数字だけは、しくみを説明せずに「表」で済ませます。**
> `-10.0` = 小さめ、`-20.0` = かなり小さい、`-80.0` = ほぼ聞こえない、という表を出すだけにします。

### 1-3. むずかしい日本語の言いかえ表

台本にこの左の列が出てきたら、必ず右に直します。

| ダメな言葉 | 言いかえ |
| --- | --- |
| 抽象化する | にている部分をまとめる |
| 汎用的な | いろいろな場面で使える |
| 冗長な | 同じことを何度も書いていて、むだが多い |
| 保守性が高い | あとから直しやすい |
| 効率的な／最適化する | むだがない／もっと速くする |
| 概念 | 考え方 |
| 定義する | どんなものかを決める／書いておく |
| 参照する | 見に行く／取ってくる |
| 生成する | 作る |
| 破棄する | 捨てる／消す |
| 実行する | 動かす |
| 判定する | 調べる／たしかめる |
| 制御する | あやつる／動かし方を決める |
| 依存する | ○○がないと動かない |
| 一意の | 世界に1つだけの／かぶらない |
| 再帰的に | （**使わない**。そういう作りにしない） |
| 計算量／オーダー | 時間がかかる／重い |

### 1-4. カタカナ語のあつかい

- 現場でそのまま使われるカタカナ語（メソッド・クラス・オブジェクトなど）は**使います**。
  ただし**初めて出すときは、必ず「用語カード」で説明します**（ルール2）。
- 現場で使われていない、かっこつけただけのカタカナ語は使いません。
  （例：「アサインする」→「わりあてる」、「コミットする」→ git の話以外では使わない）

## ルール2. 専門用語の説明のしかた

### 2-1. 用語カードの3点セット

**はじめて出す専門用語は、必ずこの形で説明します。例外はありません。**

```
【用語カード】クラス
① ひとことで  : プログラムの「設計図」
② たとえると  : たいやきの「かた」。かたが1つあれば、たいやきは何個でも作れる
③ 画面のどこ  : いま開いている Main.java の 1行目、"class Main {" と書いてある所
```

- ①「ひとことで」は **20文字以内**。長い説明はここではしない
- ②「たとえると」は、**身のまわりの物**でたとえる（食べ物・文房具・学校・料理）
- ③「画面のどこ」は、**必ず画面上の実物を赤枠で囲って見せる**。言葉だけで終わらせない

### 2-2. 用語カードのあとに必ずやること

1. **もう一度、ちがう言い方で言う**（同じ説明を2回、別の言葉で）
2. **その場で使ってみせる**（説明したら、すぐコードに書いて動かす）
3. **回の最後のまとめで、もう一度出す**

つまり、1つの用語は **1回の動画の中で最低3回** 登場します。

### 2-3. 用語の管理

- すべての用語は `03_GLOSSARY.md` に登録します
- 「何回目で初めて出すか」は `04_TERM_ORDER.md` で管理します
- **まだ説明していない用語を使ってはいけません。** どうしても必要なときは「先送り宣言」（ルール2-4）

### 2-4. 先送り宣言

説明の順番の都合で、どうしても先に書かせるしかないコードがあります。そのときは、**ごまかさずに宣言します。**

> 「ここに書いた `try` という言葉は、いまは**おまじない**だと思ってそのまま写してください。
> **第8回できちんと説明します。**」

- 先送りしたものは `04_TERM_ORDER.md` の「借りているもの一覧」に必ず書く
- **借りたら必ず返す**。予告した回で必ず説明する
- 1回の動画で先送りしてよいのは **2つまで**

## ルール3. 1本15分の作り方

### 3-1. 時間の割りふり（全回共通のテンプレート）

| 時間 | 中身 | 注意 |
| --- | --- | --- |
| 0:00 - 0:30 | **今日つくるもの**（完成した画面を先に見せる） | 「これを作ります」と動くところを見せる。やる気が出る |
| 0:30 - 1:30 | **前回のふりかえり** | 前回のコードを動かして見せる |
| 1:30 - 3:30 | **きょうの言葉**（用語カード 1〜3枚） | 1回に4枚以上は出さない |
| 3:30 - 11:30 | **いっしょに書く**（写経） | 3〜4個のかたまりに分け、**かたまりごとに動かす** |
| 11:30 - 13:30 | **動かして確認 ＋ よくある失敗3つ** | わざと間違えて、エラー画面を見せる |
| 13:30 - 14:30 | **まとめ（3行）＋ 宿題** | 今日おぼえたことを3つだけ |
| 14:30 - 15:00 | **次回予告** | 次に何ができるようになるか |

### 3-2. 「かたまりごとに動かす」の意味

8分の写経パートを、いっきに書かせてはいけません。
**「5〜20行書く → すぐ動かす → 動いた！」を3〜4回くり返します。**

理由：初心者は「50行書いてから動かして、エラー20個」で心が折れます。

### 3-3. よくある失敗3つ（毎回いれる）

各回の最後に、**わざと間違えて**エラーを見せます。

- セミコロン `;` を忘れる → 出るエラーメッセージを読む
- 大文字・小文字をまちがえる（`String` を `string` と書く）
- ファイルの置き場所をまちがえる → 画像が出ない

**エラーメッセージの読み方を教えることが、この講座のいちばんの目的の1つです。**

### 3-4. 画面の作り（動画編集のルール）

| 項目 | 決まり |
| --- | --- |
| 動画の大きさ | 1920 × 1080 |
| コードの文字の大きさ | **20pt 以上**（スマホで見ても読める） |
| 使うフォント | 等幅フォント（Consolas / Ricty など） |
| 今書いている行 | **黄色い枠**で囲む |
| 画面の分けかた | 左：Eclipse ／ 右上：ゲーム画面 ／ 右下：今日の言葉 |
| 字幕 | **全編に付ける**（音を出せない場所でも見られるように） |
| チャプター | 3-1 の7つの区切りで必ず付ける |
| 早送り | 写経部分は**早送りしない**（一緒に書けなくなるため） |

## ルール4. コードの書き方のルール

### 4-1. 量の制限

- **1回で新しく書くコードは 60行まで**
- 60行を超えそうなら、その回を2つに分ける（すでに分けてあります）

### 4-2. 名前の付け方

| 対象 | 決まり | 例 |
| --- | --- | --- |
| クラス | 英語・大文字はじまり | `Player`, `TileMap`, `BattleScene` |
| 変数・メソッド | 英語・小文字はじまり | `playerX`, `drawMap()` |
| 決まった数（定数） | 英語・全部大文字 | `TILE_SIZE`, `SCREEN_WIDTH` |
| コメント | **日本語** | `// 主人公のよこの位置` |

**変数名を `a` や `tmp` にしてはいけません。** 何が入っているか、名前で分かるようにします。

### 4-3. 使ってよい書き方・まだ使わない書き方

| 使う | 使わない（この講座では最後まで出しません） |
| --- | --- |
| `int`, `String`, `boolean`, `double` | `var`（型を目で見て覚えてほしいため） |
| `if` / `else` / `switch` | 三項演算子 `? :` |
| `for` / 拡張for / `while` | ラムダ式 `->`、ストリーム（`stream()`） |
| 配列 `int[][]` | `record`（第30回のコラムで名前だけ紹介） |
| `ArrayList` / `HashMap` | ジェネリクスの自作 `<T>` |
| クラス・継承（`extends`） | 匿名クラス、内部クラス |
| `implements`（インターフェース） | 抽象クラス（`abstract`） |
| `enum` | アノテーション（`@Override` だけは使う） |
| `try` / `catch` | 例外の自作、`finally`、try-with-resources |
| `static`（定数と Main だけ） | スレッドの高度な使い方、`synchronized` |

> **`@Override` だけは第5回で使います。**「これは印です」と説明します。

### 4-4. コメントの書き方

```java
// ---- マップを描く ----
// マップの数字を1マスずつ見ていって、その番号の絵を置く
for (int row = 0; row < mapHeight; row++) {
```

- 「かたまりの見出し」を `// ---- ○○ ----` の形で入れる
- **なぜそうするか**を書く。`i++` に「iを1増やす」と書くような、見れば分かるコメントは書かない

### 4-5. 書き直し（リファクタ）の禁止

- **一度書いたコードを、あとから大きく書き直しません。** 作り足す形で育てます
- 例外は第14回だけ（変数をクラスにまとめる回）。第13回の最後に必ず予告します

### 4-6. ファイルの置き場所

```
PureJavaRpg/                 ← Eclipse のプロジェクト
  src/                       ← Java のコード（ソースフォルダ）
  res/                       ← 絵・音・データ（★これもソースフォルダにする）
    tiles/    images/    fonts/    sounds/    maps/    data/    scripts/
```

- `res` フォルダは Eclipse で**ソースフォルダに追加**します（第8回でやります）
- 読みこみは `getClass().getResourceAsStream("/tiles/overworld.png")` の形で統一します
- こうしておくと、第30回で jar にまとめたときも、そのまま動きます

### 4-7. 文字コード

- Eclipse のプロジェクトの文字コードを **UTF-8** にします（第1回でやります）
- ファイルの改行コードは **LF** に統一します

## ルール5. 素材のルール

くわしくは `05_ASSETS.md` に書きます。ここには「絶対に守ること」だけ書きます。

1. **CC0 か SIL Open Font License（OFL）の素材だけ**を使います
2. 「商用OK」だけでは足りません。**再配布OK** かどうかを必ず確認します
   （日本の素材サイトには「商用OKだが再配布は禁止」が多く、それは使えません）
3. 使った素材は必ず `assets/CREDITS.md` に記録します
   - 素材の名前 ／ 作った人 ／ 入手先のURL ／ ライセンス ／ 入手した日
4. ライセンスの本文（`LICENSE.txt` など）を、素材と同じフォルダに入れます
5. 音は **WAV** に変換します（Java の標準機能は MP3 を鳴らせないため）

## ルール6. やってはいけないこと（まとめ）

1. 外部ライブラリを使う（LWJGL, LibGDX, Gson など、**すべて禁止**）
2. 高校から先で習う言葉・考え方を、説明の文章で使う
3. 説明していない専門用語を、だまって使う
4. 用語カードの3点セットを省く
5. 1回に60行を超えるコードを書かせる
6. 写経パートを早送りする
7. 「なんとなく動くので、これでいいです」で終わらせる
8. ライセンスを確かめずに素材を使う
9. コピペ用のコードだけ貼って、説明を飛ばす
10. 前の回で書いたコードを、予告なく大きく書き直す
