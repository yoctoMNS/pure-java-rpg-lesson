# 08. 実装の進めかた（1日ごとに指示を出す運用ルール）

`docs/01〜07` は「何を教えるか」の計画書です。このファイルは、
**その計画をコードとして実装していくときの、指示の出しかたと、私（Claude）が守る手順**を決めます。

> **想定する使い方**
> 授業の前日か当日に、その日担当する回の範囲を指示する
> → 私がその回の分だけ実装してコミット・タグ・プッシュする
> → 授業中に、前の回との**差分（git diff）を見せながら**、学生と一緒に実装をなぞる

---

## 1. 置き場所とブランチ

- コードは、この計画書と同じリポジトリの **`PureJavaRpg/` フォルダ**に作ります
  （`docs/02_RULES.md` 4-5 の構成どおり: `PureJavaRpg/src/`・`PureJavaRpg/res/`）
- **Eclipseにそのままインポートできる形**にします（`.project` / `.classpath` を含める）。
  第1回の実装時に、この骨組みを作ります
- 特に指示がなければ、**今のブランチ（`claude/rpg-engine-lecture-plan-imzqjz`）に積み増していきます**。
  main に載せる・別ブランチに切る、などご希望があれば、そのときに教えてください

## 2. 実装とタグの単位

**1話（15分ぶん）＝1コミット＝1タグ**が基本です。理由は、
**1日に何話ぶん進めても、話ごとの差分を個別に見せられる**ようにするためです。

- タグ名は計画書どおり `ep01` 〜 `ep30`
- **「困る→直す」の山場回（第7・17・24・26・28回）だけ、2タグ**にします
  - `epNN-before` … わざと不便な書きかた（コピペしたクラス、`switch` の破綻、`if` の連なり、など）
  - `epNN` … 道具（継承・抽象クラス・インターフェース）で直したあと
  - 授業ではこの2つの間の diff を見せれば、「困る→直す」がそのまま再現できます
- コミットメッセージは「第◯回 タイトル」＋その回で新しく登場した用語・道具を1行で
  （例: `第7回 NPCを足して困る → 継承で解決（Entity を追加）`）

## 3. 「1日」の区切りかた

**話数の区切りは、みなさんの授業のペースに合わせて、そのつど指示してください。**
1話＝1日でも、数話まとめて1日でも、どちらでも対応します（タグは話ごとに個別に打つので、
まとめて頼んでも差分の粒度は落ちません）。

参考までに、`01_COURSE_PLAN.md` の部（章）単位はこうなっています。

| 部 | 回 | 話数 |
| --- | --- | --- |
| 第0部 はじめる | 1 | 1話 |
| 第1部 動かす | 2〜5 | 4話 |
| 第2部 キャラクター★ | 6〜10 | 5話 |
| 第3部 マップ | 11〜14 | 4話 |
| 第4部 画面と会話★ | 15〜18 | 4話 |
| 第5部 戦闘★ | 19〜24 | 6話 |
| 第6部 仕上げ★ | 25〜30 | 6話 |

★の部には「困る→直す」の山場が入っているので、**山場回を1日の最後に置く**と、
授業の締めくくりとして分かりやすくなります（例: 第2部を2日に分けるなら「6〜9回・10回」ではなく
「6〜7回・8〜10回」のように、山場（7回）の直後で区切るのも一案です）。

## 4. 指示のテンプレート（コピペしてお使いください）

### 基本形

```
第◯回〜第◯回を実装してください。
docs/01_COURSE_PLAN.md の内容どおりに、docs/06_ARCHITECTURE.md のクラス構成で作り、
話ごとにコミットとタグ（epNN）を分けて、最後にプッシュしてください。
```

### 山場回を含むとき（自動で before/after 2タグにします。明記しなくても大丈夫です）

```
第7回を実装してください。困った状態（コピペしたNpc）を先にコミット・タグ(ep07-before)し、
そのあと Entity に直した状態を ep07 としてコミットしてください。
```

### 途中で軌道修正したいとき

```
・第◯回はこの授業では扱わないので飛ばしてください（宿題行き）
・第◯回の一時停止チャレンジの答えも別コミットで用意してください
・ここまでの回を、いま一度まっさらな環境で動作確認してください
```

## 5. 私が各回で自動的にやること

1. `docs/01_COURSE_PLAN.md` から該当回の「さわるファイル」「行数のめやす」「今日のゲームづくり」
   「今日のオブジェクト指向」を読み直す
2. `docs/06_ARCHITECTURE.md` のクラス設計・データファイル形式に沿って実装する
3. コード量がその回の上限（第1〜10回40行／第11〜20回50行／第21〜30回55行）に収まっているか確認する
4. **`javac` でコンパイルが通ることを確認する**
   - GUI（Swing）が絡む回は、この環境に画面がないため**実際の画面表示までは確認できません**。
     コンパイル確認とコードレビューで代替します。授業前に、みなさんの手元のEclipseで
     一度動作確認いただくことをおすすめします
   - `DamageCalc` など画面を伴わないロジック部分は、簡単な使い捨てテストで実際に値を確認します
5. コミット（1話1コミット）→ タグ付け → （範囲の実装が終わったら）まとめてプッシュ
6. 実装後、**その回で新しく増えたファイルと行数**を報告します

## 6. 素材（画像・音）についての注意

`docs/05_ASSETS.md` にある実際の画像・音声ファイル（CC0/OFL）は、著作権のある配布物なので
**この環境から自動ダウンロードはしません**。かわりに次のどちらかで進めます。

- **プレースホルダーを自動生成する**（推奨・デフォルト）：
  単色の四角（`BufferedImage` で生成したPNG相当）や無音・単純な音のWAVを仮に用意し、
  コードとしては完成させる。実際の見た目や音は、あとでみなさんが本物の素材に差し替える
- **みなさんが素材を用意してリポジトリに置く**：先に `res/` に素材を配置しておいていただければ、
  そのファイル名で読み込むコードを書きます

指示のときに「今回はプレースホルダーで」「素材はもう `res/` に置いた」などひとこと添えてください。
何も指定がなければ、プレースホルダーで進めます。

## 7. 授業中に差分を見せる方法

- ターミナルで前後のタグを比較: `git diff ep06 ep07`（`ep06`終了時点 → `ep07`終了時点）
- 山場回だけを見せる: `git diff ep07-before ep07`
- 1コミットだけ見る: `git show ep07`
- GitHub上で見せたい場合: `.../compare/ep06...ep07` のURLで比較画面が開けます
- 「今日はここまで実装しました」の一覧: `git log --oneline ep05..ep10`
