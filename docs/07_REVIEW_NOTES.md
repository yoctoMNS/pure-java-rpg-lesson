# 07. 見直しの記録（第1版 → 第2版）

第1版の全30回を、**教える側の目で厳しく点検した結果**と、直した内容の記録です。
なぜ今の形になっているのかを忘れないために残します。

## 0. 前提が変わったこと

| | 第1版 | 第2版 |
| --- | --- | --- |
| ゴールの言い方 | 「ドラゴンクエスト1のようなRPGのゲームエンジン」 | 「**RPGの作り方を学ぶ入門講座**。題材として、初代ドラゴンクエストにあった機能をひととおり作る」 |
| 完成物の位置づけ | （あいまい。本格的な物に見えていた） | **学習用の見本**。売り物のゲームではない、と最初にはっきり言う |

第1版は「本格的な物を作らねば」という圧力から、教え方に無理が出ていました。

## 1. 見つかった問題（重い順）

### 問題1 ★★★ 絵を出すのが早すぎて、プログラムの土台がないまま進んでいた

第1版では、第4回でウィンドウ、第5回で描画、第6回でゲームループでした。
つまり**`if` も `for` も書けない人に、`extends JPanel` と `@Override` と スレッド を写させていた**ということです。

これは「プログラミングを教えている」のではなく、**「写す作業をさせている」**だけです。
第7回でやっと `if` が出てきますが、そのときにはもう
「意味の分からない行」が30行以上たまっていて、自分では1行も直せません。

**直した内容**: 前半を組みかえ、**第3回〜第7回をコンソール（黒い画面）でのRPG作り**にしました。
絵は出しませんが、**ステータス・ダメージ計算・勝ち負け・くり返し・乱数** を扱うので、
中身はまぎれもなくRPGです。第7回の終わりに、**遊べる戦闘ゲームが完成します**。

この5回で学ぶこと（変数・if・くり返し・メソッド・クラス）は、
**そのあとの25回で毎回使うものばかり**です。ここを飛ばして先に進む理由はありませんでした。

### 問題2 ★★★ スレッドを第6回で教えていた

`Thread` と `implements Runnable` と `Thread.sleep` を第6回に置いていました。
スレッドは**目に見えない**うえ、初心者には確かめる手段がありません。
しかも `sleep` のために `try-catch` を先に借りる必要があり、借金が増えていました。

さらに技術的にも良くありませんでした。Swing の画面は「決まった1本の流れ」から
さわるのが正しく、別のスレッドから位置を変えながら画面を描くのは、
まれに表示が乱れる原因になります。

**直した内容**: **`javax.swing.Timer` に変えました。**
- スレッドの説明がいらない
- `try-catch` を借りる必要がなくなった
- 約束（インターフェース）は `ActionListener` の**メソッド1つだけ**
- 画面の扱いとしても、こちらが正しい

第1版の第6回で使っていた用語6つのうち、**3つが不要になりました**。

### 問題3 ★★★ 第14回の「コードの引っ越し」が危なかった

第1版は、第5回〜第13回で主人公の情報をバラバラの変数として書き、
第14回でそれを `Player` クラスにまとめ直す作りでした。
自分でも「この回はいちばん危ない」と書いていました。

初心者にとって**「動いていた物が動かなくなる」ほど心が折れる出来事はありません。**
そして引っ越しは、まさにそれが起きやすい作業です。

**直した内容**: **クラスを第7回で先に教えることで、引っ越しそのものをなくしました。**
絵を出し始める第8回の時点で、すでに「勇者」「モンスター」はクラスになっています。
あとは作り足していくだけです。**この講座には、書き直しの回が1つもなくなりました。**

### 問題4 ★★ 「動かないときにどうするか」を教える時間がなかった

第1版は各回の中に「よくある失敗3つ」を入れていましたが、それだけでした。
しかし未経験者にとって、いちばん必要な力は**文法の知識ではなく、
「動かないときに、自分で原因を探せること」**です。ここが弱いと、
1か所つまずいただけで講座から離れてしまいます。

**直した内容**: **第12回を「なおす回」として丸ごと1本使います。**
新しい文法は1つも出しません。エラーの文の読み方、どこまで動いているかの調べ方、
自分のコードと見本を見くらべる方法だけをやります。
場所も、絵が出はじめて一番こんがらがる時期（第8〜11回の直後）に置きました。

### 問題5 ★★ 「見ているだけ」で終わる作りだった

第1版の15分の流れには、**受講者が自分の頭で考える時間が1秒もありませんでした。**
0:30-1:30 の「ふりかえり」も、前回のコードを動かして見せるだけで、思い出す作業がありません。

写経だけで終わる講座を見た人は、**「見たことはあるが、自分では書けない」**状態になります。

**直した内容**: 15分の流れを2か所変えました。
1. ふりかえりを**クイズ**にした（質問 → 3秒待つ → 答え）。思い出す作業を必ず入れる
2. **「一時停止チャレンジ」を毎回入れた**（10:30-12:00）。
   その回で習ったことだけで書ける小さな課題を出し、動画を止めて自分で書いてもらう

30回で合計45分ほどの「自分で書く時間」ができます。
1回にまとめて練習させるより、**毎回少しずつのほうが身につきます。**

### 問題6 ★★ 1回60行は、写経の量として多すぎた

「8分で60行」は、1分あたり7〜8行です。キーの位置を探しながら、
意味も考えながらでは、まず追いつけません。追いつけないと一時停止をくり返し、
15分の動画が40分かかることになります。

**直した内容**: 回によって上限を変えました。
- 第1〜7回: **25行**まで
- 第8〜17回: **40行**まで
- 第18〜30回: **45行**まで

全体では約1,160行。第1版の約1,690行から**3割減らしました**。
減らせたのは、「本格的な物を作らなくてよい」と決まったからです。

### 問題7 ★ 「昔のしくみ」の話が、学習の役に立っていなかった

第1版には、当時のハードウェアやパスワード方式の話が4か所ありました。
面白い話ではありますが、**その回で作る物とは関係がなく**、
15分のうち1分を使う価値があるとは言えませんでした。

**直した内容**: 4か所すべて削除。空いた時間は「よくある失敗」と
「一時停止チャレンジ」に回しました。

### 問題8 ★ 完成物の規模が、入門講座に対して大きすぎた

レベル30まで、敵8種類、町が複数、セーブ3か所。これは
「作れる範囲」ではなく「作りたい範囲」で決めていました。

**直した内容**: 規模を小さくしました（`00_OVERVIEW.md` の表）。
レベルは10まで、モンスター6種類、マップ3枚、セーブ1か所。
**機能の種類は減らしていません。**1つ1つを小さくしただけです。
「大きくする」のは、受講者が自分でやれるようにしてあります（各回の宿題）。
